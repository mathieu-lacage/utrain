The new-run dialog opens on a gpu when the host has one. It used to open on
the cpu always -- the option list's first entry -- so a run meant for the gpu
trained on the cpu unless the viewer noticed the picker was wrong before
pressing enter. The cpu stays first in the list, and on a host with several
gpus the dialog opens on the first one; moving to anything else remains a
deliberate choice made visible in the field.
